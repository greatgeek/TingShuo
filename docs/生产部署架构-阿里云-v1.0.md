# 生产部署架构设计（阿里云版）v1.0

> 对应《开发与部署文档》§7 单机部署路线的落地细化。已购资源：ECS ×1、OSS Bucket ×1、RDS PostgreSQL ×1、域名 + 云解析 DNS。

## 1. 总体架构

```
                    用户浏览器（桌面 Web / 手机浏览器 / PWA）
                              │ HTTPS :443
                              ▼
┌───────────────────── ECS（1 台，公网 IP）─────────────────────┐
│  Caddy :80/:443（自动 HTTPS 证书，反代 + 静态托管）            │
│    ├─ 静态：/var/www/tingshuo/web/（桌面前端三件套）           │
│    └─ 反代 127.0.0.1:8080 → Tingshuo Server（Go 单体, systemd）│
│          ├─ /api/v1/*            REST API                    │
│          ├─ /audio/synthesize    TTS 服务端代生成（持 Key）    │
│          ├─ /generate/start|poll 材料生成任务（持 Key）        │
│          ├─ OSS SDK ──────────→ 音频资产读写                  │
│          └─ pgx ──────────────→ RDS（内网）                   │
└──────────────────────────────────────────────────────────────┘
            │ VPC 内网                        │ 内网 endpoint
            ▼                                 ▼
   ┌─────────────────┐              ┌─────────────────────┐
   │ RDS PostgreSQL   │              │ OSS Bucket（私有）   │
   │ 库：tingshuo     │              │ tingshuo-audio/     │
   │ 17 表 + 迁移管理  │              │ tingshuo-recording/ │
   └─────────────────┘              └─────────────────────┘
```

**单体原则不变**：一个 Go 进程承载 API + 前端静态托管；生成任务在服务端后台执行；音频经服务端流转或 OSS 预签名直下（见 §5）。

## 2. 组件映射（本地开发 → 阿里云生产）

| 本地（当前已验证） | 生产（阿里云） | 代码改动 |
|---|---|---|
| Go server.exe（:8080） | 同一二进制 linux-amd64 + systemd | 仅交叉编译 `GOOS=linux` |
| web/ 静态托管（server 内嵌） | Caddy 托管（或仍由 server 托管，二选一） | 无 |
| PostgreSQL 16.9（G 盘） | **RDS PostgreSQL**（内网连接串） | 仅 `DATABASE_URL` |
| RustFS :9000（minio-go） | **OSS**（S3 兼容 endpoint） | 仅 S3_* 环境变量 |
| dev 代理（/dev/llm 等） | **转正为正式端点**（§4） | 中（见 §4 决策） |
| .env.dev（含全部 Key） | .env.prod（ECS 本机，600 权限） | 无 |
| cmd/smoke 指 localhost | 指 https://域名 | 仅 PUBLIC_BASE_URL |

## 3. 网络与安全组

| 方向 | 端口 | 来源 | 用途 |
|---|---|---|---|
| 入 | 443 | 0.0.0.0/0 | HTTPS（Caddy） |
| 入 | 80 | 0.0.0.0/0 | HTTP → 301 跳转 HTTPS |
| 入 | 22 | 你的常用 IP（建议限源） | SSH 运维 |
| 入 | 8080 | **不对公网开放** | Go 服务仅监听 127.0.0.1 |
| 入 | 5432 | **不对公网开放** | RDS 走 VPC 内网 |
| 入 | 9000 | **不对公网开放** | 无（OSS 走内网 endpoint） |
| 出 | 全部 | — | LLM/Azure/OSS 外网调用 |

- **RDS 白名单**：加入 ECS 的**内网 IP**（同 VPC 免流量费、低延迟）
- **OSS**：Bucket 设为**私有读写**；RAM 子账号仅授予该 Bucket 的 PutObject/GetObject（最小权限）

## 4. 生成链路决策：服务端代生成（v1.8 架构修订）

试用版的事实形态：LLM/Azure Key 在服务端 `.env.dev`，前端经本地代理调用。生产按既定 BYOK 应由浏览器直连服务商——但存在两座山：① 服务商 CORS 未验证（部署文档 §6.4 早已标记）；② 用户需在每台设备配置 Key。

**决策（2026-10-27，延续 TTS 服务端化）**：**服务端代生成为生产主线**——

- `/dev/llm/start|poll` 升级为正式端点 `/api/v1/generate/start|poll`
- 生成任务落 RDS 的 `generation_job` 表（M0 已建，当前是内存 map）——**服务重启/发布期间任务不丢**
- LLM/Azure Key 存 ECS `.env.prod`（600 权限），按 `llm_call_log`/`tts_call_log` 观测成本
- 面向「自用 + 小圈子」的定位，Key 不再下放客户端；`DEV_PROXY=false` 关闭开发代理
- 发布给第三方用户时可再评估恢复 BYOK（FR-10.8 客户端 Key 配置保留在手册中）

**安全要点**：generate 端点要求登录 + 每用户频控（如每日 N 次生成，查 llm_call_log 计数）——防 Key 被盗刷。

## 5. 数据层

**RDS**：
- 版本选 PostgreSQL 16（与本地一致，迁移 SQL 纯标准语法直接可用）
- `cmd/migrate up` 在部署流程中执行（连接串指向 RDS）
- 阿里云默认自动备份（保留 7 天起，可在控制台调）；存储自动扩容开启

**OSS 桶规划**（S3 兼容 endpoint，如 `oss-cn-hangzhou.aliyuncs.com`）：
- `tingshuo-audio/`：句子音频（`{cache_key}.mp3`，现有 AudioKey 规则不变）
- `tingshuo-recording/`：用户录音（后续功能）
- 下载路径两选项：
  - **A. 服务端流式代理**（当前实现，单句 20—30KB，带宽可忽略）——上线默认
  - **B. OSS 预签名 GET 直下**（省 ECS 带宽）——流量上来后切换，`/audio/{id}/file` 改 302（前端 fetch blob 方式不变，仅换 302）

## 6. 域名 / DNS / HTTPS

1. 云解析 DNS：添加 **A 记录**，主机记录按喜好（如 `ting` 或 `api`），记录值 = ECS 公网 IP
2. Caddyfile（自动申请/续期 Let's Encrypt 证书，零手工）：

```
ting.example.com {
    encode gzip
    root * /var/www/tingshuo/web
    try_files {path} /index.html
    file_server
    reverse_proxy /api/* 127.0.0.1:8080
    header Cache-Control "no-cache"   # 前端迭代期
}
```

3. 首次启动 Caddy 会自动完成 ACME 验证并签发证书（需 80/443 安全组先放行）

## 7. 环境变量矩阵（ECS 上的 `.env.prod`）

```ini
DATABASE_URL=postgres://<用户>:<密码>@<RDS内网地址>:5432/tingshuo?sslmode=require
S3_ENDPOINT=oss-cn-<region>.aliyuncs.com
S3_ACCESS_KEY=<RAM子账号AK>
S3_SECRET_KEY=<RAM子账号SK>
S3_BUCKET_AUDIO=tingshuo-audio
S3_BUCKET_RECORDING=tingshuo-recording

LLM_BASE_URL=https://api.minimaxi.com/v1
LLM_API_KEY=<MiniMax Key>
LLM_MODEL=MiniMax-M3
AZURE_SPEECH_KEY=<Azure Key>
AZURE_SPEECH_REGION=southeastasia

JWT_SECRET=<openssl rand -hex 32 生成>
LISTEN_ADDR=127.0.0.1:8080
PUBLIC_BASE_URL=https://ting.example.com
DEV_PROXY=false
```

## 8. 部署流程

**首次部署**：
1. ECS 初始化：安装 Caddy；建 `/opt/tingshuo/`（二进制）+ `/etc/tingshuo/env`（.env.prod，600）
2. 本地交叉编译：`$env:GOOS='linux'; $env:GOARCH='amd64'; go build -o bin/server-linux ./cmd/server`
3. 上传：scp 二进制 + web/ + systemd 单元到 ECS
4. RDS：白名单加 ECS 内网 IP、建库 `tingshuo`、本地跑 `migrate up`（DATABASE_URL 指向 RDS）
5. OSS：建桶 + RAM 子账号 AK/SK
6. DNS：A 记录指向 ECS 公网 IP
7. systemd 启动 + Caddy 启动 → `https://域名/healthz` 验证
8. `cmd/smoke`（PUBLIC_BASE_URL 指生产）全链路冒烟

**日常更新**（自用无停机要求）：本地构建 → scp → `systemctl restart tingshuo` → healthz + 冒烟，全程 < 1 分钟。

**systemd 单元**（`/etc/systemd/system/tingshuo.service`）：

```ini
[Unit]
Description=TingShuo server
After=network.target

[Service]
WorkingDirectory=/opt/tingshuo
EnvironmentFile=/etc/tingshuo/env
ExecStart=/opt/tingshuo/server
Restart=always
User=tingshuo

[Install]
WantedBy=multi-user.target
```

## 9. 观测与成本

- **阿里云云监控**：ECS CPU/内存/带宽、RDS 连接数/磁盘——控制台默认有，超阈值短信告警
- **业务观测**：`llm_call_log` / `tts_call_log` 月度聚合 SQL（部署文档 §9.3）出真实成本；健康检查 `/healthz`
- **预期月成本**：ECS + RDS 最低配 + OSS 存储 + 流量 ≈ 两位数 RMB；LLM/TTS 走 MiniMax/Azure 各自计费（F0 层内）

## 10. 部署前 Checklist（需要你提供/确认的信息）

| # | 项 | 说明 |
|---|---|---|
| 1 | ECS 公网 IP | DNS A 记录用 |
| 2 | 域名（已购的那个） | 用于绑定（如 `ting.xxx.com`）；域名需在阿里云完成 ICP 备案（**未备案域名 80/443 会被拦截**——备案进行中可先用 IP+自签证书临时验证） |
| 3 | RDS 内网连接串 + 账号密码 | 控制台「数据库连接」页；PG 版本确认为 16 |
| 4 | OSS：Bucket 名 + Endpoint（如 oss-cn-hangzhou） | RAM 子账号 AK/SK（仅授予该桶读写） |
| 5 | ECS 登录方式 | 密码或密钥（我用于部署脚本） |
| 6 | 生成任务落库（generation_job） | 上线前实现（任务不丢），预计半天 |

## 11. 里程碑对照

- **M3 收尾**（复习页/9 步日课）不依赖生产环境，可并行
- **上线前必做**：generation_job 落库、generate 端点频控、`/audio/file` 预签名直下切换（可选）
- **上线步骤**：按 §8 首次部署 → 冒烟 → 域名访问 → 观察 3 天 → 删本地开发环境依赖（保留为开发环境）
