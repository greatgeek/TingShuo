## 1. 产品概述

### 1.1 一句话定位

以「句子」为最小学习单元的日语听说训练应用：用户每天提交 20 个新词，应用自动生成贴近生活的对话与短文，并为每句话生成真人感 TTS 音频，通过「盲听 → 跟读 → 影子跟读 → 角色扮演 → 录音对比 → 复述 → 复习」完成每天的听说闭环。

### 1.2 要解决的核心问题

| 现有工具的痛点 | 本应用的解法 |
|---|---|
| 背单词 App 只练「看和认」，听不出、说不出 | 每个词必须出现在可听、可跟读的句子中 |
| 教材音频固定、内容和自己生活无关 | AI 按用户当日词单 + 场景偏好定制生成 |
| 泛听材料难度不可控 | 生成时按 N5/N4/N3 水平与语体约束 |
| 听力素材没有配套的发音训练闭环 | 同一份材料贯穿盲听、跟读、角色扮演、录音对比、复述全流程 |
| 换设备学习记录丢失 | 三端账号同步 + 本地离线缓存 |

### 1.3 核心设计原则

1. **句级音频绑定（Sentence-Audio Binding）**：所有学习活动都发生在「一个句子 + 它的音频」上，这是全系统最核心的数据关系。
2. **生成即结构化**：AI 生成材料时直接输出句级结构（说话人、原文、假名、翻译、顺序），不做事后切分，保证「文本单元 = 音频单元 = 练习单元」三者对齐。
3. **离线优先（Offline-first）**：当天材料与音频完整缓存到本地，无网络也能完成全部学习步骤（录音、标记、练习记录），联网后同步。
4. **BYOK，Key 只存客户端本地**：大模型与 Azure TTS 的 Key 由用户在前端填写、仅加密存储在设备本地——**永不上传服务端、永不跨设备同步、不进任何日志**；客户端直连服务商调用，服务端不持有任何第三方 Key。
5. **同句同参数只生成一次**：以 `(句子文本, 音色, 语速, 风格, TTS引擎版本)` 为缓存键全局去重，避免重复计费。
6. **听说优先（功能裁决原则）**：任何功能取舍先问「能否让耳朵和嘴巴变强」。文字是脚手架不是目标——默认收起、按需展开；能说的不打字（语音优先作答）；纯文字练习（拼写、自由听写）不做。

### 1.4 范围边界（本期不做）

- iOS 原生（桌面已由 Web 版覆盖，见 §7.5；架构预留）
- 社区、音色市场、UGC 内容分享
- 发音评测（第二阶段评估 Azure Speech Pronunciation Assessment）
- 语法讲解、系统性课程（只做围绕词单的听说训练）
- 英语 / 韩语等多语言学习（**P2 路线，见 §12**；schema 已预留 `target_language` 字段，将来扩展无需数据迁移）

### 1.5 产品路线：自用起步，保留发布能力

一期定位为开发者本人日常自用（单实例、单用户部署），但**架构不做单用户假设**：账号体系、`user_id` 隔离、同步游标、生成限额开关全部保留，仅默认放宽/关闭。自用阶段验证有效后的发布路径见 §3.15 发布就绪清单，届时零重构上线。

## 2. 用户画像与核心场景

### 2.1 目标用户

- **主要**：已过 N5 / 备考 N4—N3 的自学者，词汇量 800—3000，能看懂但「听不出、不敢说」。
- **次要**：日语二外学生、因兴趣（动漫/旅行）学日语的上班族，每天能投入 20—40 分钟。

### 2.2 一个典型学习日（用户故事）

> 早上通勤，小林打开 App，粘贴今天的 20 个词（从课本/生词本复制）。App 提示「材料生成中，约 1 分钟」。到站后材料已就绪：3 段便利店/车站场景对话 + 1 篇短文，每个词都出现在句子里，汉字带假名注音。
>
> 午休 15 分钟：盲听第一段对话两遍 → 逐句看文本跟读 → 换 Nanami/Keita 双音色角色扮演 A/B → 对卡壳的句子点「标记难点」。
>
> 晚上 15 分钟：短文影子跟读 → 用自己的话复述并录音，与标准音频交替回放 → 完成 5 个即问即答。
>
> 第二天早上，App 推送复习列表：昨天的 12 个易错句 + 5 个待复现词，听音频选句子、看中文说日语。

### 2.3 核心使用循环

```
输入词单 → 生成材料包 → 生成句级音频 → 学习日课（9 步）→ 标记难点
     ↑                                                    ↓
     └────────── 第 2/3/7 天复习 ←── 易错句/词自动进复习池 ←──┘
```

## 3. 功能需求细化

优先级定义：**P0** = MVP 必须；**P1** = 第二阶段；**P2** = 远期。每条需求附验收标准（AC, Acceptance Criteria）。

### 3.1 模块 FR-1：每日词单输入与管理

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-1.1 | 单条录入：`单词｜读音｜词性｜中文`，竖线或制表符分隔，读音可留空（由生成服务补全） | P0 |
| FR-1.2 | 批量粘贴：多行文本一次性导入，自动解析、逐行校验，错误行高亮并支持逐条修正；**解析结果以词列表实时预览**（读音/词性/中文/状态标签），提交前可核对、点标签改状态 | P0 |
| FR-1.3 | CSV / TXT 文件导入（UTF-8，表头可映射） | P0 |
| FR-1.4 | 词状态标记：新词 / 重点词 / 已掌握 / 易错，学习过程中可随时切换 | P0 |
| FR-1.5 | 生成前预检：不足 5 词或超过 40 词给出提示；重复词自动去重 | P0 |
| FR-1.6 | PDF / 图片 OCR 导入词单 | P2 |
| FR-1.7 | 词库全局视图：跨日期搜索、按状态筛选、导出 CSV | P1 |

**FR-1 验收标准**

- AC-1.1：粘贴 20 行格式合法的词单，预检通过后可一键提交生成。
- AC-1.2：粘贴含 3 行格式错误的文本，错误行被标出且不阻塞其余 17 行提交。
- AC-1.3：同一词在当日词单中重复出现时，只保留一条并提示。

### 3.2 模块 FR-2：AI 材料生成

材料生成在**客户端**执行：用本地 Key 直连 LLM 生成材料 JSON，交服务端做 schema 校验、kagome 振り仮名/音调核词典增强并落库；生成进度是客户端本地状态，无需任务队列与轮询。

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-2.1 | 一次生成完整「材料包」：3 个生活微场景对话（每个 4—6 轮）+ 1 篇独白短文（60—90 秒朗读量，约 200—300 字） | P0 |
| FR-2.2 | 词覆盖约束：每个词至少出现 1 次，重点词出现 2 次；生成结果附「新词复现表」（词 → 出现的句子 ID 列表）供校验 | P0 |
| FR-2.3 | 输出结构化：每句含 `说话人、原文（汉字）、整句假名串（仅作校验参考）、中文翻译、句子序号、所属材料、角色`；短文句子附段落号 | P0 |
| FR-2.4 | 生成 5 个即问即答（针对对话/短文内容的口头问题，附参考答案） | P0 |
| FR-2.5 | 生成 5 个替换造句任务（围绕重点词，给中文提示 + 参考答案） | P0 |
| FR-2.6 | 水平与语体约束：按 N5/N4/N3 控制语法与词汇难度；默认です・ます体，可配置混入自然口语（对话内 A 用普通体） | P0 |
| FR-2.7 | 场景偏好：从用户设置的主题（便利店/车站/午饭/约朋友/家/公司…）中选择当日 3 个场景 | P0 |
| FR-2.8 | 自然度约束（prompt 内置）：不为塞词写不自然的句子；若无法自然使用某词，允许标记 `skipped` 并在复现表中说明原因 | P0 |
| FR-2.9 | 重新生成单个材料（如只重生成第 2 段对话），不影响其余 | P1 |
| FR-2.10 | 生成参数模板（用户可保存自己的生成偏好组合） | P1 |
| FR-2.11 | 假名校验：后端用 kakasi/kuroshiro 类库校验注音与原文汉字对应，不一致则触发一次修复重试 | P1 |
| FR-2.12 | **振り仮名注音（显示主形态）**：后端用分词器（kagome，Go 原生）对原文分词、取词典词级读音，渲染为汉字头顶振り仮名；LLM 整句假名串仅作交叉校验，不一致句触发修复重试。**原文永远保持自然日语（汉字）形态，假名只作头顶注音，可一键隐藏，不替换原文** | P0 |
| FR-2.13 | **即时场景**：词单输入增加可选「今日情境」一句话描述（如「下午要去邮局寄包裹，顺便药妆店买东西」），材料围绕当天真实生活生成——几小时后要经历的事，正是耳机里在听的日语。「贴近生活」的极致形态；无描述时回落到场景主题（FR-2.7） | P0 |
| FR-2.14 | **音调核（pitch accent）**：生成时输出词级音调核（①②…标注），点词卡与句子详情显示，kagome 词典读音配套。日语说得地道的关键维度（雨↓飴↑类近音词全靠它区分） | P1 |
| FR-2.15 | **搭配卡（collocations）**：为每个重点词生成 2—3 个高频搭配（带例句），仍是句子级单元——可单独听、可入复习池。背搭配比背单词更接近「说」的最小单位 | P1 |
| FR-2.16 | 语体变体：同句一键生成敬体/常体双版本音频，训练语感切换（复用 sentence→audio 管线） | P2 |

**FR-2 验收标准**

- AC-2.1：提交 20 个词后 3 分钟内拿到完整材料包（含全部结构化字段）。
- AC-2.2：材料包中每个非 skipped 词的复现表条目非空。
- AC-2.3：材料 JSON 通过 schema 校验（见 §5.3 GenerationOutput 结构），任何字段缺失视为生成失败并自动重试一次。

### 3.3 模块 FR-3：TTS 音频生成（Azure Neural TTS）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-3.1 | 接入 Azure Speech Neural TTS，日语音色：Nanami（ja-JP-NanamiNeural，女）、Keita（ja-JP-KeitaNeural，男） | P0 |
| FR-3.2 | 对话按角色分配音色（A=Nanami / B=Keita，可交换），短文用单独可配音色 | P0 |
| FR-3.3 | **按句子粒度生成**，一句话一个音频文件；禁止整篇一个文件 | P0 |
| FR-3.4 | 语速档位：慢速 0.85x / 正常 1.0x / 稍快 1.15x（映射 Azure SSML prosody rate），默认正常 | P0 |
| FR-3.5 | 全局缓存去重：缓存键 = hash(规范化句子文本 + 音色 + 语速 + 风格 + 引擎版本)，命中则不调用 Azure | P0 |
| FR-3.6 | 批量生成：材料生成成功后自动触发当日全部句子 TTS（可关）；失败句进入重试队列，最多 3 次 | P0 |
| FR-3.7 | 单句重新生成（换音色/语速重生成一条） | P0 |
| FR-3.8 | 音频格式：MP3 24kHz 48kbps（体积/质量折中），元数据记录时长与文件大小 | P0 |
| FR-3.9 | 朗读风格 / 情感（SSML `mstts:express-as`，如 cheerful） | P1 |
| FR-3.10 | TTS 服务商抽象层，预留多供应商切换 | P1 |
| FR-3.11 | 连续语速微调 0.7x—1.3x（prosody rate 任意值，实现时按档归并缓存键），难句从 0.75x 逐级往上爬 | P2 |
| FR-3.12 | **客户端直连 Azure（BYOK）**：TTS 由客户端携本地 Key 调用；调用前先查服务端 audio_asset（全局去重判定仍在服务端，命中即不调），生成的 MP3 经预签名 PUT 上传对象存储并登记 cache_key | P0 |

**FR-3 验收标准**

- AC-3.1：同一天重复打开课程，不产生新的 TTS 调用（命中缓存，可在管理后台看调用数）。
- AC-3.2：对话播放时 A/B 声色明显区分。
- AC-3.3：批量任务中个别句子失败不阻塞其余句子，失败句在客户端显示可单独重试。
- AC-3.4：Azure/LLM Key 只存客户端本地——服务端数据库、同步流量、日志中均不出现 Key；服务端代码不引用任何第三方 Key 配置。

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-4.1 | 每句全局唯一 ID（ULID），句子与音频为 1:N（不同音色/语速/版本） | P0 |
| FR-4.2 | 音频元数据：音色、语速、时长、文件 URL、缓存状态、生成时间 | P0 |
| FR-4.3 | 播放模式：单句播放、单句循环、AB 区间复读、连续播放整段、整课顺序播放 | P0 |
| FR-4.4 | 盲听模式：隐藏全部文本，仅显示播放控制与句子序号点阵 | P0 |
| FR-4.5 | 「当前句重复 N 遍 + 间隔」的跟读辅助（播放后留 2 倍时长空拍供跟读） | P1 |
| FR-4.6 | 离线缓存：当日课程音频由客户端下载到本地，无网可完整学习 | P0 |
| FR-4.7 | 每句可携带用户侧标注：标记难点、笔记 | P0 |
| FR-4.8 | 文本脚手架原则：日课各步骤原文默认收起，点击展开；展开后汉字头顶振り仮名（FR-2.12，可一键隐藏，隐藏时即为纯自然日语文本）；**中文翻译默认隐藏，点「中译」按钮后显示**（最后一级脚手架，在假名之后）；跟读先出声模仿，听不准再看文字（盲听全隐藏） | P0 |
| FR-4.9 | 通勤模式（泛听）：零交互自动连播当天全部材料，熄屏可用，难点句自动播两遍。日课 30 分钟是精听，通勤泛听是免费加餐，决定听力输入量上限 | P1 |

**FR-4 验收标准**

- AC-4.1：断网状态下打开当日课程，全部句子可播放，学习步骤（含录音）可完成，联网后记录同步。
- AC-4.2：同一句子切换语速档位，切换后 3 秒内可播放（新档位需生成时给出转圈提示）。

### 3.5 模块 FR-5：学习日课流程（9 步）

日课是一个有引导的步骤流（Stepper），每步可跳过、可回退，进度持久化。

| 步骤 | 内容 | 需求 | 优先级 |
|---|---|---|---|
| 1 盲听 | 不看文本听对话/短文 1—2 遍，抓场景与关键词；结束后可选「听懂了几成」自评（用于复习权重） | FR-5.1 | P0 |
| 2 看文本跟读 | 逐句播放，显示原文+假名+翻译，用户跟读 2—3 遍；可标记难点 | FR-5.2 | P0 |
| 3 影子跟读 | 音频连续播放不停顿，用户延迟半句同步跟说；提供进度条与当前句高亮；**可开录音**，结束后回放复盘与音频的差距 | FR-5.3 | P0 |
| 4 角色扮演 | 选择扮演 A 或 B，对方角色的句子自动播放，轮到用户时静音显示文本，可开录音 | FR-5.4 | P0 |
| 5 录音回放 | 对任意句子录音，录音与句子绑定；支持「标准音频 → 我的录音」交替播放对比 | FR-5.5 | P0 |
| 6 复述 | 合上文本，用 3—5 句话复述对话/短文并录音；显示要点词提示 | FR-5.6 | P0 |
| 7 即问即答 | 回答 5 个生成问题，每题可听参考答案音频；答案可录音保存 | FR-5.7 | P0 |
| 8 替换造句 | 5 个造句任务，**语音优先**提交（打字为备选）；显示参考答案 | FR-5.8 | P1 |
| 9 标记难点 | 汇总本课标记的难点句/词，一键加入复习池 | FR-5.9 | P0 |

**FR-5 验收标准**

- AC-5.1：日课中途退出（杀进程），重进后回到上次步骤。
- AC-5.2：9 步全流程在 30 分钟内可完成（20 词/天的标准配置）。
- AC-5.3：步骤 4 角色扮演中，非用户角色的句子由 TTS 播放，用户角色句子不自动播放音频。

### 3.6 模块 FR-6：录音与发音对比

**FR-7 验收标准**

- AC-7.1：第 D 天学完的句子，若被标记难点，则出现在 D+2、答对后 D+6（2→再答对×2=4 天后…依调度规则）的到期列表中。
- AC-7.2：复习全部完成后，下次到期日期更新正确。

> **复习调度的科学依据**：依赖认知心理学中复现度最高的两个效应——**间隔效应**（spacing effect，Cepeda et al. 2006 荟萃分析）与**测试效应**（testing effect，主动回忆 > 被动重看）。间隔值不采信任何「艾宾浩斯时间表」（网络流传的 8 周期复习表并非 Ebbinghaus 本人结论，且原始实验基于无意义音节），而是**由实际表现驱动**（答对 ×2、答错重置）——答错本身就是最强的难度信号，故无需 SM-2 式难度系数。5 种复习形式全部是主动提取，这一点比具体间隔数字更重要。将来可平滑升级 FSRS 类算法（复习记录已完整保存）。

## 5. 数据模型设计

### 5.1 实体关系总览

```
User 1───N DailyLesson 1───N Material(Dialogue/Passage) 1───N Sentence
                     │                                        │
                     │ 1──N Word(当日词单, 经 lesson_word 关联) │ 1───N AudioAsset
                     │                                        │ 1───N Recording
                     │                                        │ 1───1 ReviewItem(可空)
                     └── N GenerationJob(课的生成/TTS任务)

PracticeRecord：Sentence × 步骤类型 的流水记录（append-only）
```

核心不变式：**文本单元 = 音频单元 = 练习单元 = 复习单元 = 录音单元**，全部挂在 `sentence` 上。

### 5.2 服务端表结构（PostgreSQL）

> ID 统一用 ULID（时间有序，便于同步游标）。以下列出一期建表字段（省略通用 `created_at / updated_at`）。

**user** — 用户

```sql
id TEXT PK, email TEXT UNIQUE, password_hash TEXT,
nickname TEXT,
target_language TEXT NOT NULL DEFAULT 'ja',  -- 学习语言：'ja'/'en'/'ko'（P2 多语言预留）
level TEXT CHECK(level IN ('N5','N4','N3')),  -- 语义随 target_language 映射：ja=JLPT N5-N3，en=CEFR A1-B2，ko=TOPIK I-II（多语言落地时改为应用层校验）
scene_prefs JSONB,        -- ["便利店","车站",...]
style_prefs JSONB,        -- {"voice_a":"Nanami","voice_b":"Keita","passage":"Nanami",
                          --  "rate":1.0,"politeness":"masu_with_casual_mix"}
tts_auto_gen BOOLEAN DEFAULT true, deleted_at TIMESTAMPTZ
```

**daily_lesson** — 每日课程

```sql
id TEXT PK, user_id TEXT FK, lesson_date DATE,
status TEXT CHECK(status IN ('draft','generating','ready','failed')),
word_count INT, generate_params JSONB,   -- 本次生成用的参数快照
UNIQUE(user_id, lesson_date)             -- 一天一课（一期简化）
```

**word** — 单词（全局词库，跨课程）

```sql
id TEXT PK, user_id TEXT FK, surface TEXT,     -- 单词（汉字形）
reading TEXT, pos TEXT, meaning TEXT,
mastery TEXT DEFAULT 'new' CHECK(mastery IN ('new','key','learned','weak')),
UNIQUE(user_id, surface, reading)
```

**lesson_word** — 词单关联（词在课程中的快照状态，如本课是否重点）

```sql
lesson_id TEXT FK, word_id TEXT FK, is_key BOOLEAN,
occurrence_count INT, skipped BOOLEAN, skip_reason TEXT,
PRIMARY KEY(lesson_id, word_id)
```

**material** — 材料（对话或短文）

```sql
id TEXT PK, lesson_id TEXT FK,
type TEXT CHECK(type IN ('dialogue','passage')),
scene TEXT,           -- 场景标签
role_a TEXT, role_b TEXT,  -- 对话角色名（短文为 NULL）
title TEXT, sort_order INT
```

**sentence** — 句子（核心表）

```sql
id TEXT PK, material_id TEXT FK, lesson_id TEXT FK,
sort_order INT, speaker TEXT,        -- A/B 或 独白
text TEXT,                           -- 原文（日语含汉字；英语原文本身即音文一致）
kana TEXT,                           -- 整句假名串（可空）：仅作校验参考，不直接展示；英语可空或 IPA；韩文表音，通常为空
ruby_tokens JSONB,                   -- 振り仮名结构（P0 主显示形态）：[["会計","かいけい"],["を",null],...]，由分词器词典读音产出
translation TEXT,                   -- 中文
para_no INT                          -- 短文段落号（对话为 0）
```

**audio_asset** — 音频资产（TTS 缓存与去重的落点）

```sql
id TEXT PK, sentence_id TEXT FK,
cache_key TEXT UNIQUE,      -- hash(sentence_norm + voice + rate + style + engine_ver)
voice TEXT, rate REAL, style TEXT,
format TEXT,                -- 'mp3'
duration_ms INT, size_bytes INT,
storage_url TEXT,           -- 对象存储地址
status TEXT CHECK(status IN ('pending','ready','failed')),
engine_ver TEXT, generated_at TIMESTAMPTZ
```

> `cache_key` 全局唯一：不同用户、不同课程的相同句子命中同一条资产（句子本身由生成决定，撞车概率极低，但换音色/语速重生成时准确分流）。实际以 `(voice, rate, style, engine_ver, sentence_id)` 生成。

**practice_record** — 练习流水（append-only，同步友好）

```sql
id TEXT PK, user_id TEXT FK, sentence_id TEXT,
step TEXT CHECK(step IN ('blind_listen','read_along','shadowing','roleplay',
                         'record','retell','qa','substitution')),
device_id TEXT, client_created_at TIMESTAMPTZ,   -- 客户端时间，用于排序
payload JSONB   -- 如 {"self_rating":0.6} / {"marked":true}
```

**recording** — 用户录音

```sql
id TEXT PK, user_id TEXT FK, sentence_id TEXT, lesson_id TEXT,
step TEXT, duration_ms INT,
local_path TEXT,           -- 客户端本地路径（离线录音的临时落点）
storage_url TEXT,           -- 云端地址：录音默认上传（FR-6.3），与音频同一存储层
device_id TEXT, client_created_at TIMESTAMPTZ
```

**review_item** — 复习项（句子级）

```sql
id TEXT PK, user_id TEXT FK, sentence_id TEXT UNIQUE,  -- 一句一个复习项
source TEXT CHECK(source IN ('marked','blind_low','retell_stuck','manual','score_low')),
interval_days INT DEFAULT 1, error_count INT DEFAULT 0,
due_date DATE, last_result TEXT,  -- 'pass'/'fail'
mastered BOOLEAN DEFAULT false
```

**qa_item / substitution_item** — 即问即答与造句任务

```sql
id TEXT PK, lesson_id TEXT FK, type TEXT CHECK(type IN ('qa','substitution')),
prompt TEXT, prompt_kana TEXT, prompt_translation TEXT,
answer TEXT, answer_kana TEXT,  -- 参考答案（同时作为 TTS 句子入 sentence 表）
sort_order INT
```

**generation_job** — 生成任务（LLM 与 TTS 统一）

```sql
id TEXT PK, lesson_id TEXT FK,
type TEXT CHECK(type IN ('material','tts','tts_single')),
status TEXT CHECK(status IN ('pending','running','succeeded','failed','partial')),
progress INT,          -- tts: 已完成句数/总句数
error TEXT, result_ref TEXT, attempts INT DEFAULT 0
```

**word_review_link / 同步游标表 sync_cursor**

```sql
-- 设备同步游标（服务端记录每个设备拉到哪了）
user_id TEXT, device_id TEXT, last_event_id TEXT, PRIMARY KEY(user_id, device_id)
```

```jsonc
  "qa_items": [ { "prompt": "...", "answer": "..." } ],
  "substitution_items": [ { "word_id": "...", "prompt_zh": "...", "answer": "..." } ],
  "word_occurrence": { "w_001": ["s_007","s_012"], "w_002": "skipped:专有名词不适合本场景" }
}
```

服务端必须校验：全部词在 `word_occurrence` 中有交代（出现或 skipped）；句子数量范围（对话每段 8—12 句、短文 8—12 句）；schema 不通过自动重试 1 次。

### 5.4 客户端本地库（SQLite / drift）

镜像服务端核心表（lesson / material / sentence / audio_asset / practice_record / recording / review_item），另加本地专用表：

```sql
audio_cache(   -- 本地音频文件登记
  audio_id TEXT PK, local_path TEXT, downloaded_at TEXT, source TEXT  -- 'wifi'/'any'
)
outbox_sync(   -- 待上行同步队列（append-only 事件）
  id TEXT PK, table_name TEXT, row_id TEXT, op TEXT, payload JSONB, synced INT DEFAULT 0
)
```

本地库就是离线学习的唯一数据源；同步 = 上行 flush outbox + 下行按 `updated_at` 游标拉取。

## 6. API 设计

REST + JSON，前缀 `/api/v1`，JWT Bearer 认证。生成类接口全部异步（返回 job，客户端轮询或等推送）。

### 6.1 端点总览

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /auth/register, /auth/login | 注册 / 登录（返回 JWT + refresh token） |
| GET/PUT | /me | 用户信息与偏好 |
| POST | /lessons | 提交当日词单，创建课程（status=draft） |
| POST | /lessons/{id}/generate | 触发材料生成（幂等：ready 状态直接返回） |
| GET | /lessons/{id} | 课程全量（材料+句子+音频元数据，一次拉全） |
| GET | /lessons?from=&to= | 历史课程列表 |
| GET | /jobs/{id} | 任务状态（progress） |
| POST | /audio/regenerate | 单句重生成：`{sentence_id, voice?, rate?}` |
| GET | /audio/{id}/file | 音频文件 302 → 对象存储签名 URL（或直接下发预签名 URL） |
| GET | /reviews/due?date= | 到期复习列表 |
| POST | /reviews/{id}/result | 提交复习结果 `{result:'pass'/'fail'}`，返回新 due_date |
| POST | /sync/push | 上行 outbox 事件批量 flush |
| GET | /sync/pull?cursor= | 下行增量（按 updated_at 游标） |

### 6.2 关键接口示例

**提交词单并生成（两个调用）**

```http
POST /api/v1/lessons
{
  "lesson_date": "2026-10-27",
  "words": [
    {"surface": "精算", "reading": "せいさん", "pos": "名詞", "meaning": "一起结账", "is_key": true},
    ...
  ],
  "params": {"scenes": ["便利店","车站","午饭"], "level": "N4"}
}
→ 201 { "lesson_id": "01JAX...", "status": "draft" }

POST /api/v1/lessons/{lesson_id}/generate
→ 202 { "job_id": "01JAY...", "type": "material" }
```

**轮询任务**

```http
GET /api/v1/jobs/01JAY...
→ {"status":"succeeded","lesson":{"status":"ready"}, "next_job":{"type":"tts","progress":"38/62"}}
```

材料生成成功后服务端**自动**入队 TTS 批量任务，客户端轮询 job 时同时看到两级进度。

**拉取课程（含绑定好的音频）**

```jsonc
// GET /api/v1/lessons/01JAX...
{
  "lesson": { "id": "01JAX...", "date": "2026-10-27", "status": "ready" },
  "words": [ { "id": "w_001", "surface": "精算", "occurrences": ["s_007"] } ],
  "materials": [
    { "id": "m_01", "type": "dialogue", "scene": "便利店", "role_a": "店員", "role_b": "客",
      "sentences": [
        { "id": "s_001", "sort": 1, "speaker": "B", "text": "これ、お願いします。",
          "kana": "これ、おねがいします。", "translation": "我要买这个。",
          "audios": [
            { "id": "a_001", "voice": "Keita", "rate": 1.0, "duration_ms": 1800,
              "url": "/api/v1/audio/a_001/file", "status": "ready" } ] } ] } ]
}
```

客户端拿到后整体落本地 SQLite；音频按 `audios[].url` 下载入 `audio_cache`。

**上行同步（outbox flush）**

```http
POST /api/v1/sync/push
{ "events": [
    {"table":"practice_record","op":"insert","row":{...},"client_created_at":"..."},
    {"table":"review_item","op":"update","row":{...}} ] }
→ 200 { "accepted": 2, "server_time": "..." }
```

### 6.3 错误与限流

- 统一错误体：`{"error":{"code":"WORD_COUNT_INVALID","message":"..."}}`
- 每用户生成限额：材料生成 5 次/天，TTS 单句重生成 50 次/天（FR-3 成本护栏，超限返回 429）
- 幂等：`POST /lessons` 同日重复提交返回既有课程 + 409/合并提示

### 7.3 播放器统一模型

所有页面的音频交互收敛到一个控制器，五种模式共享同一句队列：

```
SentencePlayerController
├─ mode: single | loopSingle | abRepeat | continuous | blindAll
├─ queue: List<Sentence>           // 当前材料或复习列表的句子序列
├─ rate: 0.85 | 1.0 | 1.15
├─ gapForShadowing / gapForReadAlong // 跟读时句间插入静音
└─ roleplay(role: 'A'|'B')          // 跳过用户角色的句子（仅高亮文本）
```

### 7.4 日课页各步骤的界面要点

| 步骤 | 界面要点 |
|---|---|
| 1 盲听 | 全屏纯播放器：波形 + 句子序号点阵（无任何文本）；结束后弹「听懂几成」滑条 |
| 2 跟读 | 双栏：上=句子列表（当前句高亮，点击任意句播放），下=当前句大字原文（汉字头顶振り仮名，可隐藏；翻译按需展开） |
| 3 影子 | 整段连续播放不可暂停；当前句滚动高亮；倒计时显示剩余 |
| 4 角色扮演 | 聊天界面：非用户角色句子自动播（头像+气泡），用户句子显示麦克风按钮，可长按录音 |
| 5 录音对比 | 句子选择器 + 「听标准 → 听我的」两个按钮，A/B 交替自动播放 |
| 6 复述 | 隐藏文本，仅给关键词卡片；录音完成后展开原文对照 |
| 7 问答 | 逐题卡片：显示问题（可听）→ 录音回答 → 展开参考答案 |
| 8 造句 | 输入框 or 录音，提交后显示参考答案 + diff 高亮目标词 |
| 9 汇总 | 本课难点句列表（来自步骤 1/2 的标记）勾选加入复习池 → 完成日课 |

### 7.5 平台策略与桌面端适配

- **平台矩阵**：**Android = Flutter 原生**（自用直接 sideload APK，无需上架）；**桌面（Windows/macOS）= Flutter Web（PWA）**，同一仓库编译为 Web，挂在自有 VPS 上，浏览器打开即用。
- **为什么桌面走 Web**：零安装零维护——免去 Windows 打包签名与 macOS 公证（个人开发者最容易卡住的环节）；刷新即最新版；自用的桌面场景（在家/公司、在线、坐下来学 15 分钟）恰好避开 Web 的短板（离线、常驻）；真正需要离线和熄屏常听的通勤场景由 Android 端承担。
- **前端依赖**：just_audio / record 均有 web 实现；麦克风权限要求 HTTPS 安全上下文（VPS 域名 + Caddy 自动证书，见部署）。
- **演进路径**：将来若需常驻/托盘/全局快捷键，用 **Tauri 壳**把 Web 版包成安装版（P1），前端零重写；发布阶段桌面分发变为可选项（FR-15）。
- **UI 适配**：桌面浏览器两栏布局（左导航+右内容），移动端底部 tab；PWA 可「安装到桌面」获得独立窗口与图标。

## 8. 后端设计

### 8.1 技术选型

- **语言/框架**：Go（Gin 或标准库 + chi），单体起步，按模块分包；后期再拆服务。
- **数据库**：PostgreSQL 16（JSONB 存生成参数快照）。
- **对象存储**：S3 兼容接口（自选供应商，如 R2/OSS/COS），音频对象只写不删（删除仅断引用 + 定期 GC）。
- **任务队列**：一期不引入 MQ，直接用 PostgreSQL 表 `generation_job` + 单实例轮询 worker（`FOR UPDATE SKIP LOCKED`）；量大后再换。
- **LLM**：OpenAI 兼容接口可配置（国产/海外模型可切换），`base_url + model` 走配置。
- **TTS**：Azure Speech SDK（Go 里用 REST API 即可：`/cognitiveservices/v1`，SSML body）。

> 部署形态（无状态实例 + 托管 PG + 对象存储）、本地开发环境、备份与升级等运维事项，详见《日语听说学习应用-开发与部署文档》。
>
> **BYOK 演进（v1.5）**：LLM/Azure Key 只在客户端后，`generate`/`tts` 模块退化为「schema 校验 + kagome 增强 + 存储 + 去重判定」，`generation_job` 队列在 MVP 不再需要（生成是客户端行为，进度即本地状态）；保留表结构，供发布后可选的「官方代生成」模式复用。

### 8.2 单体分模块

```
backend/
├── cmd/server/          # HTTP 入口
├── internal/
│   ├── auth/            # JWT、注册登录
│   ├── lesson/          # 词单、课程 CRUD
│   ├── generate/        # LLM 材料生成：prompt 组装、schema 校验、落库
│   ├── tts/             # Azure 调用、cache_key 去重、对象存储上传
│   ├── review/          # 复习调度（纯函数可单测）
│   ├── sync/            # outbox flush + 游标拉取
│   └── jobq/            # generation_job 轮询 worker（material → 自动链式入队 tts）
└── pkg/                 # ulid、ttsclient、llmclient、storage
```

### 8.3 生成链路（时序）

```
客户端                API                 worker                外部
  │ POST /lessons      │                    │                    │
  │──────────────────▶│ 校验词单、建 lesson │                    │
  │ POST /generate     │                    │                    │
  │──────────────────▶│ job(material) 入队 │                    │
  │                    │  ◀── 轮询取 job ───│                    │
  │                    │   worker A:        │                    │
  │                    │   组装 prompt ───────────────▶ LLM     │
  │                    │   schema 校验(不过重试1次)              │
  │                    │   sentence 逐句落库 │                    │
  │                    │   job(tts) 自动入队 │                    │
  │                    │   worker B:        │                    │
  │                    │   逐句: cache_key ──┼──── 命中? 复用    │
  │                    │   未命中 → SSML ──────▶ Azure TTS      │
  │                    │   mp3 → 对象存储, 更新 audio_asset     │
  │ GET /lessons/{id}  │                    │                    │
  │◀──────────────────│ 全量返回(未ready句显示生成中)             │
```

要点：

- TTS worker 逐句独立失败/重试（attempts ≤ 3），partial 状态允许客户端开始学习已就绪句子。
- 长句（>150 字符）按标点预切分为多个 TTS 请求再拼接，避免 Azure 单请求限制。

### 8.4 TTS SSML 模板

```xml
<speak version="1.0" xml:lang="ja-JP"
       xmlns="http://www.w3.org/2001/10/synthesis"
       xmlns:mstts="https://www.w3.org/2001/mstts">
  <voice name="ja-JP-NanamiNeural">
    <mstts:express-as style="{style}">
      <prosody rate="{rate}">{sentence_text}</prosody>
    </mstts:express-as>
  </voice>
</speak>
```

输出：`audio-24khz-48kbitrate-mono-mp3`。

### 8.5 复习调度算法（服务端纯函数）

```go
func NextInterval(curDays int, result Result) int {
    if result == Fail {
        return 1
    }
    next := curDays * 2
    if next > 30 { next = 30 }
    if next < 2  { next = 2 }
    return next
}
// 首次入池 interval=1；due_date = today + interval
```

（P1 若接发音评测，score < 60 等价 Fail 自动入池/重置。）

### 8.6 安全设计

- Azure/LLM Key：**服务端不持有**（BYOK，见原则 4）；开发调试用 `.env`（gitignore），绝不进代码库。
- 音频下载：`/audio/{id}/file` 校验归属后 302 到**预签名 URL**（10 分钟有效），不代理流量。
- 客户端只持 JWT（短效）+ refresh token；登出吊销 refresh。
- 峰值限流：按 user_id 维度（NGINX 或中间件均可）。

## 9. 成本估算与限额策略

按标准配置估算（20 词/天 → 3 段对话 + 1 篇短文 + 10 个问答/造句参考答案 ≈ **55—65 句/天**，平均 25 字符/句）：

| 项目 | 用量/天 | 用量/月 | 单价（参考） | 月成本/用户 |
|---|---|---|---|---|
| Azure TTS 字符 | ~1,500 字符 | ~45,000 | F0 免费层 50 万字符/月；S0 $15/百万 | **免费层内**；超出后 <$0.01 |
| LLM（材料生成） | 1 次调用（in ~2K / out ~4K tokens） | ~30 次 | 视模型 ¥0.001—0.02/次 | < ¥1 |
| 对象存储 | ~60 个 MP3（~30KB/个 ≈ 2MB） | ~60MB | R2 免出口流量 | <$0.01 |
| 数据库/服务器 | — | — | 单体 + Postgres 单实例 | 固定成本 |

**结论**：BYOK 后服务端零 LLM/TTS 变动成本（费用随 Key 归属由用户自付，上表为用户侧参考），**真正的成本是开发与维护**。护栏仅在未来提供「官方代生成」模式时才需要，MVP 不启用：

1. 每用户每日 TTS 字符上限（默认 10 万，防脚本滥用）；
2. 单句重生成 / 天限额 50 次（FR-3.7 接口层）；
3. 材料生成 5 次/天（重生成材料入口也有计数）；
4. 服务端对 Azure 调用记录字符数，超阈值告警。

## 12. 多语言扩展设计（P2 预留）

### 12.1 语言无关与语言专属的边界

核心闭环中**没有任何环节是日语专属的**——数据模型（§5）、9 步日课（FR-5）、5 种复习形式（FR-7.3）、间隔重复算法（§8.5）、TTS 去重与句级绑定（FR-3.5 / FR-4）全部按语言无关设计。Azure Neural TTS 对英语（en-US-JennyNeural、GuyNeural 等）与韩语（ko-KR-SunHiNeural、InJoonNeural）提供同接口的 Neural 音色，服务端只换 `voice name` 与 SSML 的 `xml:lang`。

### 12.2 各语言适配差异

| 环节 | 日语（现状） | 英语 | 韩语 |
|---|---|---|---|
| 注音（sentence.kana） | 全假名注音，LLM 生成 | 可空，或放 IPA 音标 | 韩文表音，通常为空 |
| 汉字标假名（FR-2.3） | 生成时注音 | 删除 | 删除 |
| 语体约束（FR-2.6） | です・ます体 ↔ 普通体 | 无对应，改为「正式 / 口语」 | 존댓말 ↔ 반말，与日语同构 |
| 句子切分 | 。！？ | 处理 `.` 缩写（Mr.、e.g.） | 。！？，与日语相同 |
| 水平分级 | JLPT N5—N3 | CEFR A1—B2 | TOPIK I—II |
| 假名校验（FR-2.11） | kakasi / kuroshiro | 不需要 | 不需要 |
| 发音评测（FR-6.5，P1） | Azure 支持 | Azure 支持 | Azure 支持 |

结论：**韩语适配成本接近零**（语体、句读、分级逻辑同构）；英语主要是去掉注音、换分级体系。

### 12.3 本期已做的预留（为扩展免迁移）

1. `user.target_language` 字段已入 schema（默认 `'ja'`），一期不暴露设置入口（FR-10.7 标 P2）。
2. `sentence.kana` 语义泛化为「注音列（可空）」，字段名不变，扩展时无需 DDL。
3. 音色、语体、分级、场景等生成参数本就通过 `generate_params` / `style_prefs` JSONB 快照传递，天然按语言配置。

### 12.4 多语言落地时的改动清单（P2）

- 服务端：`level` 的 DB CHECK 放宽为应用层校验（按 `target_language` 映射 N5-N3 / A1-B2 / TOPIK）；prompt 模板按语言分文件；TTS 音色列表配置化
- 客户端：设置页语言切换入口（FR-10.7）；注音 UI 按 kana 列有无自适应
- 复习/练习模块：零改动（句级、语言无关）
