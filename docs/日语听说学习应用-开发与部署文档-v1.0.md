## 1. 部署形态总览

### 1.1 设计原则

- **无状态应用实例**：Go 容器零本地卷，任何实例可随时删除重建；全部状态外置。
- **代码不变，只换配置**：本地/生产同一二进制，差异全部收敛在 `.env`（数据库 DSN、对象存储 endpoint、第三方 Key）。
- **文件不经过应用进程**：音频下载与录音上传走对象存储**预签名 URL 直连**（§8.6 设计），实例不碰文件字节、不占实例带宽。
- **worker 不落临时文件**：TTS 结果内存生成 → 直接 stream 写对象存储（唯一要注意别引入状态的代码点）。

### 1.2 拓扑

```
            ┌─────────────────────────────┐
            │  无状态应用实例（可 N 个）    │
用户/客户端 ─▶│  Go：API + LLM/TTS worker  │  ◀── 镜像任意拉起，随时替换
            │  + Web 静态托管，零本地卷    │
            └──────┬──────────────┬───────┘
                   │ DSN           │ S3 协议
                   ▼               ▼
           托管 PostgreSQL     对象存储（OSS / R2 / MinIO）
           （业务数据+任务队列） （音频+录音，预签名直传直下）
```

### 1.3 状态清单（唯一不可再生项 = 数据库）

| 数据 | 位置 | 丢失后果 |
|---|---|---|
| PostgreSQL 数据 | 托管实例（自动备份） | ❗ 课程/复习进度/学习记录，必须保住 |
| TTS 音频 | 对象存储 | 可再生：`cache_key` 决定性生成，按 audio_asset 表重放即可 |
| 录音 | 对象存储 | 半可再生（客户端本地有副本，可补传） |
| 应用实例 | — | 无状态，随时重建 |

### 1.4 平台矩阵

| 端 | 形态 | 备注 |
|---|---|---|
| Android | Flutter 原生 APK（sideload） | 离线学习、通勤泛听主力 |
| 桌面（Win/macOS） | Flutter Web（PWA），由应用实例托管 | 浏览器打开即用；麦克风需 HTTPS 上下文 |

## 2. 本地开发环境搭建

### 2.1 基础工具（Windows / Mac 等价）

| 工具 | 用途 | 备注 |
|---|---|---|
| Go 1.22+ | 后端 | 纯 Go，无 CGO |
| Flutter 3.x stable | 客户端 | `flutter doctor` 全绿为准 |
| PostgreSQL 16 | 本地数据库 | **原生安装即可，不需要 Docker** |
| MinIO | 本地对象存储（模拟 OSS/R2） | 官方单文件 exe/二进制，双击即起 |
| air | Go 热重载 | 有 Windows 版 |
| cloudflared | 把本地 8080 暴露为公网 HTTPS | 移动端 4G 联调用 |

> Windows 上**不强制 WSL2/Docker**：Postgres 官方安装包 + MinIO 原生 exe 即为完整依赖（推荐路线 B，出错面更小）。若偏好贴近生产容器形态可选 Docker Desktop + WSL2（路线 A），compose 文件见附录。

### 2.2 初始化清单（一次性）

1. 装 Go / Flutter / Postgres / MinIO，Postgres 建库：`CREATE DATABASE tingshuo;`
2. MinIO 起服务，控制台建 bucket：`audio`、`recording`
3. 仓库根目录复制 `.env.example` → `.env.dev`，填入 Azure TTS Key（F0 免费层）与 LLM Key
4. `go run ./cmd/migrate` 建表
5. 验证：`go run ./cmd/smoke`（全链路冒烟，见 §6）

### 2.3 环境配置分层

```
.env.dev    DATABASE_URL=localhost:5432   S3_ENDPOINT=localhost:9000   → 本地调试
.env.prod   DATABASE_URL=RDS内网地址        S3_ENDPOINT=oss-cn-hongkong…  → 生产
```

同一二进制，`--env-file` 切换；`.env*` 全部进 `.gitignore`，Key 永不进仓库。

### 2.4 本地也能测的功能（无需任何证书）

- **录音（Web 端）**：浏览器对 `localhost` 豁免 HTTPS 要求，`flutter run -d chrome` 可直接测麦克风；
- **真机连本地后端**：Android 真机连同一 Wi-Fi，API base 指向电脑局域网 IP（dev 构建开 cleartext HTTP）；
- **全链路 LLM/TTS**：本地直连真实 API（F0 免费层随便调）。

## 3. 日常开发流程

### 3.1 仓库结构

```
tingshuo/
├── backend/
│   ├── cmd/server        # HTTP 入口
│   ├── cmd/migrate       # 建表/迁移
│   ├── cmd/smoke         # 全链路冒烟（Go 写，跨平台）
│   └── internal/         # auth/lesson/generate/tts/review/sync/jobq（同设计文档 §8.2）
├── app/                  # Flutter（Android + Web 同仓库）
├── deploy/
│   ├── compose.dev.yml   # 可选：Postgres+MinIO 容器版
│   ├── compose.prod.yml  # 生产：app + caddy
│   └── Caddyfile
├── .env.example
└── .editorconfig
```

### 3.2 每日循环

```powershell
# 起本地依赖（原生安装路线 B 下 Postgres/MinIO 已是系统服务，可跳过）
# 起后端（热重载）
air
# 起 Web 客户端（另一终端）
flutter run -d chrome
# 起真机调试（可选，API base 指局域网 IP）
flutter run -d <device_id>
```

### 3.3 移动端外网联调（零部署）

```powershell
cloudflared tunnel --url localhost:8080
# → 得到 https://xxx.trycloudflare.com
# Android 真机在 4G 下直接连这个地址（HTTPS，免备案、免域名、免证书）
```

适合在部署前验证移动端完整体验；地址每次随机，不用于长期。

### 3.4 联调完成 → 提交

- 提交前跑 `go test ./...` 与 `go run ./cmd/smoke`；
- 语义化提交；`main` 分支保持可部署状态。

## 4. 数据库管理与迁移

- 迁移工具：`golang-migrate`（SQL 文件版本化，`migrations/000001_init.up.sql` / `.down.sql`）；
- 本地建库：`go run ./cmd/migrate up`；
- 生产发布时同一命令跑一次（幂等，compose.prod 的 app 容器入口自动执行 `migrate up && server`）；
- 破坏性变更（删列/改类型）一律走「加新列 → 双写 → 切读 → 删旧列」三步，不依赖 down 回滚；
- 种子数据：`go run ./cmd/seed`（内置 N5 示例词单，用于联调演示）。

## 5. 工程规范（跨平台防坑）

| 规范 | 做法 |
|---|---|
| 换行符 | 仓库 `.editorconfig`（LF）+ `git config core.autocrlf input` |
| 任务脚本 | 一律 Go 程序（`go run ./cmd/xxx`），不写 bash/PowerShell 脚本 → 三平台零成本 |
| 临时文件 | 代码用 `os.TempDir()`，不写死 `/tmp` |
| 路径拼接 | `filepath.Join`，不手拼 `/` |
| Key 管理 | 只在 `.env*`（gitignore）；代码从 env 读，缺 Key 启动即报错 |
| 音频 worker | TTS 结果内存 → stream 写对象存储，不写本地临时文件 |
| 端口 | 本地固定 8080（API）/5432（PG）/9000-9001（MinIO），文档与代码一致 |

## 6. 测试与全链路冒烟

### 6.1 测试分层

| 层 | 内容 | 运行 |
|---|---|---|
| 单元 | 复习调度纯函数（§8.5 NextInterval）、cache_key、词单解析、kagome 分词注音 | `go test ./...` |
| 集成 | 生成 schema 校验、任务队列状态机（本地 PG） | `go test -tags=integration ./...` |
| 冒烟 | 真实全链路 | `go run ./cmd/smoke` |

### 6.2 冒烟脚本覆盖的链路（对齐 M1 验收；BYOK 后冒烟脚本模拟「客户端」角色）

```
注册测试账号 → 提交 20 词词单 → 冒烟脚本以 .env.dev 的 Key 直连 LLM 生成材料（模拟客户端）
→ 上传材料 JSON：服务端 schema 校验 + kagome 振り仮名增强 → 落库到 ready
→ 查询各句缓存状态 → 直连 Azure 生成未缓存句（模拟客户端 TTS）→ 预签名上传 MP3 → 登记 cache_key
→ 复拉课程全量，校验每句有音频元数据 → 预签名下载首个音频
→ 上传一条假录音（预签名 PUT）→ 提交一条复习结果 → 查询到期列表
→ 打印各步耗时与 LLM/TTS 调用字符数
```

冒烟通过 = 本地环境全绿，可以开始做客户端联调。**建议连续 5 天用不同词单跑冒烟**——验证的不是单次成功，而是 LLM 输出不稳定时失败重试是否兜得住。

### 6.3 系统主要流程总览（8 条）

| # | 流程 | 路径 |
|---|---|---|
| 1 | 词单流程 | 输入/粘贴/导入 → 逐行解析预览（状态标签）→ 提交（可附即时情境） |
| 2 | 材料生成（客户端 BYOK） | 本地 Key 直连 LLM → 材料 JSON → 服务端 schema 校验（重试 1 次）→ kagome 振り仮名/音调核增强 → 落库 |
| 3 | TTS 流程（客户端 BYOK） | 查服务端 cache_key → 未命中才调 Azure → MP3 预签名 PUT 上传 → 登记 audio_asset |
| 4 | 学习日课（9 步） | 盲听 → 跟读 → 影子 → 角色扮演 → 录音对比 → 复述 → 问答 → 造句 → 汇总入池 |
| 5 | 复习流程 | 三源自动入池（标记/低自评/卡壳）→ 到期列表 → 5 种形式 → 结果 → NextInterval 调度 |
| 6 | 同步流程 | 客户端 SQLite 唯一工作副本 → outbox 上行 flush + 游标下行拉取 → 冲突 last-write-wins |
| 7 | 离线流程 | 当日课程缓存 → 断网完成全部 9 步（含录音）→ 联网补传 |
| 8 | 点词/查词（P1） | 点词 → JMDict 本地层 → LLM 例句 → 例句走管线变可听句 |

### 6.4 关键验证清单（按 失败成本 × 出错概率 × 无替代性 排序）

**第一梯队：M1 冒烟必过（失败 = 闭环不存在）**

| 流程 | 验证点 | 为什么关键 |
|---|---|---|
| 材料生成链路 | 连续 5 天词单冒烟；schema 失败重试兜底；词复现表非空；skipped 如实说明（AC-2.1/2.2/2.3） | LLM 输出是全项目唯一不受控输入，风险最集中（R1/R2） |
| TTS + 去重 + 绑定 | 同句重复打开**零 Azure 调用**（AC-3.1）；**Web 端 CORS 直连 Azure 第一天就试**（BYOK 后唯一新增硬风险，不行立刻换方案/服务商）；单句失败不阻塞（AC-3.3） | 计费护栏 + Web 端可行性 |

**第二梯队：M2/M3 验收（失败 = 用户信任崩塌）**

| 流程 | 验证点 | 为什么关键 |
|---|---|---|
| 播放器 SentencePlayer | 真机完整日课：五模式、角色扮演跳过用户句（AC-5.3）、语速档 3 秒可播（AC-4.2） | 9 个学习步骤全跑在它上面；Flutter 音频插件是已知风险（R4） |
| 同步与冲突 | 演练 A（见下）；答对/答错/重置三路径 due_date（AC-7.1/7.2） | 自建最复杂的基础设施；丢学习记录 = 信任崩塌 |
| 复习调度 | 纯函数单测 + 数据模型走查 | 逻辑简单但数据错了影响一个月后才发现 |

**最易忽略、上线后最致命：离线优先（AC-4.1）**——开发时永远有网，固定用演练 B 验证。

### 6.5 三个固定演练剧本（每个里程碑通关必做一次）

**演练 A · 双端冲突（M3）**
手机与电脑**同时**开同一日课：同时标难点、同时做同一句复习、其中一端保持离线几分钟后联网 → 验证 outbox flush、游标拉取、last-write-wins 全程**不丢任何一条记录**。

**演练 B · 飞行模式（M3）**
日课进行到第 4 步时开启飞行模式 → 完成剩余全部步骤 + 录音 + 标记 → 关闭飞行模式 → 验证记录一条不少地补传（AC-4.1 的原样复刻）。

**演练 C · 真机日课（M2）**
Android 真机完整跑 9 步（约 30 分钟，AC-5.1/5.2/5.3），重点：播放器五模式、角色扮演音色切换（AC-3.2）、中断退出后回到原步骤。

| 速查 | 流程 → 验证载体 → 里程碑 |
|---|---|
| 生成链路 | 冒烟 × 5 天词单 → M1 |
| TTS + 去重 + CORS | 冒烟 + 浏览器直连试 → M1 |
| 播放器 | 演练 C → M2 |
| 同步冲突 | 演练 A → M3 |
| 复习调度 | 单测 → M3 |
| 离线 | 演练 B → M3 |

## 7. 生产部署

### 7.1 地域决策（香港 vs 大陆备案）

| 方案 | 组成 | 年成本 | 代价 |
|---|---|---|---|
| **A. 阿里云香港**（默认） | 轻量服务器 HK + RDS PG Serverless + OSS 香港 | ¥700—1000 | 无（免备案、当天可用） |
| **B. 大陆 + 备案** | 大陆轻量（活动价）+ RDS Serverless + OSS | ¥350—650 | 备案 1—3 周（一次性）；国内访问更快 |

两方案代码与镜像**完全相同**，只差 `.env.prod` 里的 DSN 与 OSS endpoint——决定可以拖到上线前一周。备案方案省约 ¥30/月，换来的是国内双端访问质量；见 §10 决策记录 D1。

### 7.2 生产资源清单（方案 A）

- 阿里云轻量应用服务器 2C2G（香港）
- RDS PostgreSQL Serverless（香港，自动备份 + 按时间点恢复）
- OSS bucket：`audio` / `recording`（香港）
- 域名一个（¥10—30/年）→ A 记录指向轻量服务器 IP
- ACR 容器镜像服务（个人版免费）

### 7.3 首次部署步骤

```
1. 镜像构建推送：    docker build -t registry.../tingshuo:v1.0.0 . && docker push …
2. 服务器准备：      安装 docker；git clone deploy/（或 scp）
3. 填 .env.prod：    DSN、OSS 凭证（**不需要 Azure/LLM Key**——BYOK，Key 在客户端）
4. 起服务：          docker compose -f compose.prod.yml up -d
                   （入口：migrate up && server；Caddy 自动签 HTTPS 证书）
5. DNS 解析生效，浏览器验证 Web 端；Android App 配置正式 API 地址
```

### 7.4 生产 compose 组成

| 容器 | 说明 |
|---|---|
| app | 无状态，无本地卷；`restart: always`；健康检查 `/healthz` |
| caddy | 自动 HTTPS（Let's Encrypt）+ 反代 8080；无本地证书状态可丢 |

RDS 与 OSS 是云服务，不在 compose 内。

### 7.5 安全基线

- RDS 走内网地址（与应用同地域），公网白名单仅开发机 IP（临时）；
- OSS bucket 私有，只经预签名 URL 访问（10 分钟有效期）；
- 服务端**不持有** Azure/LLM Key（BYOK：Key 由用户在客户端填写、只存设备本地）；开发调试用的 Key 只在本机 `.env.dev`（gitignore）；
- 防火墙仅开 80/443。

## 8. 备份与恢复

### 8.1 策略（托管时代大幅简化）

| 层 | 手段 | 频率 |
|---|---|---|
| RDS 自动备份 | 云服务自带 + 按时间点恢复 | 持续 |
| **主权导出** | `pg_dump -Fc tingshuo` 导出到本地电脑 + OSS | **每月 1 次，cron** |
| 音频/录音 | OSS 数据 11 个 9 持久性，不单独备份；极端情况可按 cache_key 重放 | — |

核心原则不变：**唯一不可再生的数据是数据库**，一条每月 pg_dump 就保住了全部。

### 8.2 恢复演练（每季度 1 次，10 分钟）

```
新服务器：docker compose -f compose.prod.yml up -d（连恢复后的 RDS 或新 RDS）
RDS：控制台从备份恢复 / 导入 pg_dump
验证：浏览器登录 → 历史课程可播放 → 冒烟通过
```

## 9. 升级、回滚与观测

### 9.1 升级

```
docker compose pull app && docker compose up -d app   # 新镜像 tag，滚动替换
```

无状态实例升级 = 换镜像重启，秒级；DB 迁移由容器入口自动执行（§4 约束保证向后兼容）。

### 9.2 回滚

```
APP_IMAGE_TAG=v1.0.2 docker compose up -d   # 指回旧 tag
```

### 9.3 观测（自用够用版）

- 应用日志：`docker logs` / journald，按天滚动；
- 成本观测：`llm_call_log` / `tts_call_log` 表记录每次调用的字符数与耗时（设计文档 §8.1 可观测要求），一条 SQL 出月度账单；
- 健康检查：`/healthz`（DB ping + OSS ping）；
- 不引入 APM/Prometheus，量级完全不需要。
